Загляни в  след  файловой системы

NTFS молча записывает каждое изменение на диске в журнал $UsnJrnl:$J — создание, удаление, переименование, перезапись. JournalTrace читает этот журнал с выбранного тома и превращает его в живой, фильтруемый поток файловой активности.

01 / Что это такое

USN Journal — «чёрный ящик» вашего диска

01

Журнал, который нельзя обмануть

Update Sequence Number Journal — служебный файл $UsnJrnl:$J на каждом томе NTFS. Файловая система пишет в него запись при каждом изменении: файл создан, удалён, переименован, перезаписан.

cmd.exeFileCreate
~DF8C21.tmpFileDelete
doc.tmp → doc.pdfRename_New_Name
02

Каждая запись — улика

Даже когда файл удалён и его имя исчезло из каталога, USN-запись остаётся: метка времени, код причины, идентификатор файла в MFT, имя и путь родителя.

14:32:07timestamp
Frn 0x3F2Afile ref
reason mask0x0001 0002
03

Для форензики

Восстанавливайте таймлайн инцидента: какие исполняемые файлы появлялись, что переименовывалось, какие следы малвари остались в журнале после «зачистки».

powershell.exeFileCreate
x.ps1 → x.pngRename_New_Name
lsass.dmpFileDelete

Для аудита и анализа инцидентов

Аномальная волна удалений в 3 часа ночи, массовые переименования, перезапись данных — JournalTrace показывает поток событий в реальном времени, а не постфактум.

05

Журнал — в читаемый поток

JournalTrace парсит USN-записи с выбранных томов, разрешает идентификаторы файлов и даёт вам язык фильтров: включения, исключения, OR-условия — всё в одном GUI.

name:.exe!!svchostfilter
name:.pf;reason:deletemulti-col
trace found!match
02 / Возможности

Всё, что нужно, чтобы читать журнал как открытую книгу

Парсинг USN Journal с выбранных томов

Подключайте один или несколько томов NTFS одновременно — JournalTrace читает поток USN-записей через нативный Win32 API (обёртка StCroixSkippers для UsnJournal) и декодирует каждую запись в человекочитаемый вид.

C:\ NTFS · $UsnJrnl:$J · чтение
D:\ NTFS · $UsnJrnl:$J · чтение
E:\ exFAT · журнал недоступен

Коды причин событий

Каждая USN-запись несёт битовую маску причин. JournalTrace расшифровывает её в понятные флаги:

FileDeleteRename_New_Name BasicInfoChangeData_Overwrite FileCreate

Продвинутая фильтрация

Язык выражений поверх журнала — комбинируйте условия как нужно:

&&включение (AND) !!исключение (NOT) ||OR-условие

Мультиколоночные фильтры

Точка с запятой задаёт условия для разных колонок одновременно:

name:.pf;reason:delete

OpenByFileId

Идентификаторы файлов из USN-записей разрешаются в реальные пути через OpenByFileId:

Frn 0x0003F2A1→C:\Users\admin\…

04 / Как это работает

Три шага до таймлайна файловой системы

01

Выберите том NTFS

JournalTrace обнаружит доступные тома и подключится к USN Journal каждого выбранного диска.

C:\ NTFS · $UsnJrnl:$J
D:\ NTFS · $UsnJrnl:$J
02

Примените фильтры

Включайте, исключайте, комбинируйте — язык фильтров сужает поток до именно тех событий, которые важны.

filter: name:.exe!!svchost
03

Анализируйте результаты

Отфильтрованный поток записей с временем, причиной, путями — готовый таймлайн для расследования.

14:32:07 FileDelete ~DF.tmp
14:32:11 Rename doc→doc.pdf
05 / FAQ

Частые вопросы

JournalTrace работает на десктопных версиях Windows с NTFS начиная с Windows 7 — там, где служба USN Journal доступна и включена для тома. На серверных редакциях (Server 2012+) тоже всё работает: $UsnJrnl:$J — стандартный механизм NTFS.

Да. Чтение $UsnJrnl:$J и особенно разрешение идентификаторов файлов через OpenByFileId требуют доступа к низкоуровневым структурам тома, поэтому JournalTrace нужно запускать от имени администратора.

Отфильтрованный поток записей можно сохранить для отчёта и дальнейшего анализа в инструментах таймлайнов — формат плоской таблицы легко импортируется. Следите за обновлениями в репозитории.

Да, полностью. JournalTrace распространяется по лицензии GNU GPL v3.0: используйте, изучайте исходники и делайте форки. Исходный код на C# открыт — github.com/spokwn/JournalTrace.
